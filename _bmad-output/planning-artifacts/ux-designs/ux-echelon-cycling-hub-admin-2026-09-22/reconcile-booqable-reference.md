# Booqable reference reconciliation

Input: [user screenshot](imports/booqable-dashboard-reference.png). This is an organizational reference, not an instruction to copy every visible feature.

| Reference idea | Disposition |
|---|---|
| Going out and Coming back side by side | Adopted for Windows tablet/laptop and other laptops by the user. |
| Clearly placed date controls | Adopted, with one shared filter above both directions. Separate panel filters are deliberately replaced. |
| Distinct day headings and easy-to-scan times | Adopted; day groups follow the selected Madrid period. |
| Phone organization | Screenshot does not establish phone behavior. User explicitly chose a direction switch. |
| Order identity and fulfillment counts | Relevant existing source fields retained; readiness and lifecycle counts follow Echelon Workshop definitions, not Booqable reservation quantities. |
| Blue palette, sidebar, avatars/contact-heavy rows | Not approved as a new identity or row requirement. User chose existing Echelon Subframe styling. |
| All / Pickups / Deliveries tabs | Not adopted by this UX run; not required by the confirmed dashboard contract. |
| Run report, View late, View all, Load more | Not adopted merely because visible. Any eventual partial delivery must be explicit under the source contract. |
| Booqable navigation, support bubble, scan-a-barcode | Outside dashboard UX scope. |

No approved qualitative idea was dropped. Shared date filtering is an explicit user decision; responsive switching comes from discussion rather than the screenshot. Detailed readiness, warnings, sync confidence and drawer/task navigation are supplied by the confirmed Echelon sources and user decisions.
